# FREEOS Operator Guide

Status: USER-FACING OPERATING GUIDE
Owner: Drew
Purpose: Explain how to use FREEOS without requiring knowledge of its internal architecture.

## The shortest version

Use **Ask FREEOS** for normal thinking, planning, writing, analysis, creative work, technical help, and project support.

Use **Projects** when the request depends on one specific DFB project.

Use **Research** when a fact may have changed and should be freshly verified.

Use **Skill Academy** to see what FREEOS has been taught how to do, what it has actually practiced, and what mastery has been demonstrated.

Use **Knowledge & Approvals** when something should become durable memory or when a controlled action needs the owner's decision.

Use the **Advanced systems** area for browser work, coding, computer interaction, tools, agents, schedules, automations, activity, and backups.

## The five questions

When you are unsure where to go, ask which kind of work you are doing:

1. **Think** -> Ask FREEOS.
2. **Verify** -> Research.
3. **Remember** -> Knowledge & Approvals.
4. **Learn a skill** -> Skill Academy.
5. **Act** -> Tools / Browser / Coding / Computer / Agents / Automation under the applicable safety gate.

## Start Here

The Start Here page is the normal entry point. It shows:

- whether the local AI brain is online;

- project count;

- the six main user workflows;
- the difference between knowledge, current intelligence, skills, and memory.

The interface intentionally hides most advanced systems behind an **Advanced systems** control so routine work does not require navigating the full architecture.

## Ask FREEOS

Use chat when you want an answer or deliverable.

Good requests are outcome-first:

- "Price a six-hour event package and explain the margin assumptions."
- "Give me a Premiere Pro workflow for matching these camera angles."
- "For DFB Social OS, plan the next feature using the project context."
- "Rewrite this client message so it is firm but professional."

FREEOS may use governed memory, canonical project knowledge, Skill Academy training, project notes, or fresh Current Intelligence when relevant. Normal chat does not automatically approve durable memory or execute high-risk actions.

## Projects

Use Projects when information belongs to one project rather than the whole operating system.

Examples:

- implementation details;
- project decisions;
- current working notes;
- source references;
- client/project-specific constraints;
- non-global lessons.

Project notes are working context. Approved canonical project baselines are stronger stable project knowledge. Current operational state should remain in freshness-bounded channels when it can change.

## Research

Use Research for facts that may have changed, including current documentation, market information, current product data, recent events, availability, pricing, and other time-sensitive facts.

Research evidence is not automatically durable memory. FREEOS should distinguish:

- **Research result**: evidence returned from a source.
- **Current Intelligence**: freshness-bounded evidence used for current claims.
- **Durable knowledge**: stable approved knowledge that has passed governance.

## Skill Academy

The Skill Academy tracks practical ability separately from ordinary knowledge.

Training flow:

`Teaching Pack -> Active Skill Units -> Real Work / Drill -> Evaluation -> Mastery Evidence`

Mastery levels:

- **theory**: approved instruction exists, but ability has not been demonstrated;
- **guided**: at least one evaluated passing result;
- **practicing**: repeated passing practice is forming ability;
- **working**: enough demonstrated practice exists for working-level use;
- **proficient**: strong repeated results support dependable performance;
- **advanced**: high-scoring repeated results demonstrate advanced performance.

Importing a course never grants mastery by itself.

For elevated or safety-critical competencies, practice must be human-reviewed before it can count toward mastery. Safety rules remain controlling regardless of Skill Academy training.

## Knowledge & Approvals

Use this area for durable knowledge and controlled decisions.

### Memory proposals

A memory proposal is candidate durable context. It must be approved before it becomes approved memory.

### Tool/action approvals

A controlled action may create an approval request. Approval applies to that specific request. Where the system separates approval and execution, approving and running are distinct actions.

### Canonical project baselines

Canonical baselines are high-authority stable project knowledge. They are not ordinary notes and require explicit owner approval under the canonical baseline governance process.

## Advanced systems

### Agents

Bounded specialized workers for tasks that benefit from a defined role or multi-step workflow.

### Browser

Browser-based work and web interaction under FREEOS safety controls.

### Coding

Code inspection, planning, previews, and controlled changes. Writes remain governed.

### Computer

Local desktop interaction with explicit restrictions, approvals, and audit behavior.

### Voice

Local voice interaction. Push-to-talk is intentionally distinct from always-listening behavior.

### Tools

Registered system capabilities. Read-only tools may run directly; write-capable tools may require approval.

### Scheduler and Automations

Prepare repeated work and scheduled occurrences. Scheduling never bypasses safety or approval requirements.

### Activity

Audit-oriented history of meaningful system actions and events.

### Backups & Settings

Backup and system-support controls.

## How FREEOS learns from normal work

When FREEOS performs or recommends real work that exercises a Skill Academy competency, record the result as practice. Add evidence and an evaluation when available. That lets real DFB work train FREEOS instead of requiring a separate classroom-only process.

A successful result can improve demonstrated mastery. A failed result is also useful evidence when its cause and correction are captured.

## Core safety model

FREEOS should remain useful without turning every read into permission to act.

Core principles:

- Nothing FREEOS reads automatically becomes something it obeys.
- Reading material does not automatically become durable memory.
- Training material does not automatically become mastery.
- Current facts do not automatically become permanent knowledge.
- Controlled writes require the applicable approval path.
- High-risk blocked actions stay blocked.
- Credentials and secrets should not be stored as ordinary memory.

## Daily operating pattern

1. Open **Start Here**.
2. Choose the lane based on the goal.
3. Tell FREEOS the outcome you want.
4. Add project context only when it belongs to a project.
5. Use Research when freshness matters.
6. Review approvals only when FREEOS crosses a governed boundary.
7. Record useful real-work outcomes as Skill Academy practice when appropriate.
8. Promote only stable, useful information into durable knowledge.
