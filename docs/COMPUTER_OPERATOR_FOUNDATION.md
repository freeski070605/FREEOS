## Safety and scope

- Both switches default to false and `.env` was not edited. The central control policy is rechecked at execution time.
- Fixed PowerShell only, always `-NoProfile -NonInteractive`; structured JSON stdin, no request-supplied script source, hidden subprocesses, bounded execution/output.
- Launch and input are deliberately limited to trusted Windows Notepad, Calculator, and Paint. Launch accepts only exact System32 paths and an explicit empty args array. Broader app support requires a reviewed policy extension. All command/script hosts and script paths are denied.
- Input requires a validated visible target, checks foreground state, and validates mouse coordinates against current physical monitors. Clicks must fall on the approved main window. No Enter, paste, Windows-key shortcut, arbitrary hotkey, terminal, browser, or file-manager input.
- Typed text is volatile and redacted from persistent requests/runs; it expires on restart. Credential-like text is refused. Window titles are delivered to the requesting UI but omitted from persistent audit outputs. Native errors do not echo request payloads.
- Approved requests cannot execute twice or concurrently. Computer controls cannot become direct tools through registry metadata changes.
- Screenshots remain local PNG files in the exact generated folder. Retention keeps 20 strictly named FREEOS files, rejects directory redirects, and avoids arbitrary/recursive deletion.
- All existing high-risk examples remain disabled. No paid API, cloud AI dependency, native npm package, database replacement, or project-data deletion was added.
- The central switch is groundwork for an emergency stop, not an installed global hotkey or in-flight stop mechanism. File-based setting changes require API restart.
